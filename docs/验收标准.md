# MTC 验收标准（第一阶段 · 能跑通技术验证的骨架）

> **版本** v2.0 ｜ **日期** 2026-09-22 ｜ 生效版
> **用途**：把 `docs/接口契约.md` 里的**成功 / 失败 / 边界**，写成"**照着做一遍就能判定**"的检查项。
> **★本清单是书面检查，不是自动化测试。** 骨架阶段由人按步骤执行一遍；将来实现稳定后，能自动化的项再自动化。
> **与契约的关系**：每项都标注**对应契约章节**。**契约改了，本表必须同步改**；反之本表发现契约没写的行为，要回头补进契约。
> **执行纪律**：逐项执行 → 记录结果 → 不通过时**记下 traceId 和现象**，不要只写"失败"。

## 〇、前置条件（缺一项就不能开始）

| # | 前置 |
| --- | --- |
| P1 | 五个服务（前端 / 后端 / AI 服务 / 数据库 / 缓存）能各自启动 |
| P2 | `.env` 已按 `.env.example` 配置好；**真实的 `.env` 不进版本库** |
| P3 | 两个健康检查地址可访问（`/actuator/health`、`/health`） |
| P4 | 有一条可登录的演示账号（**只在演示开关打开时存在**，见 `docs/占位清单.md` 第二节） |

## 一、启动与健康　（契约 二 · 6.6 · 6.7）

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| A1 | 三服务能起 | 按一键启动流程启动 | 三个服务都能访问，进程不反复重启 |
| A2 | ⑤ 不套信封 | 请求 `/actuator/health` | 返回 200，body 是 `{"status":"UP"}`——**里面没有 code / message / data / traceId** |
| A3 | ⑤ 的语义 | 查看配置 | **明确写出**用的是 liveness 还是 readiness；**readiness 应包含数据库**、liveness 不应包含外部依赖 |
| A4 | ⑥ 不套信封 | 请求 `/health` | 返回 200，body 是 `{"status":"ok"}`，**不套信封** |
| A5 | 大小写是有意的 | 对比 ⑤ 与 ⑥ | ⑤ 是 `UP`、⑥ 是 `ok`，**两者不同不是 bug** |
| A6 | 健康检查也带追踪头 | 看响应头 | 两个健康检查的响应里都有 `X-Trace-Id` |
| A7 | AI 服务不对外 | **验收环境**下把 `ai-service` 的 `ports` 那一行去掉（或用 `docker-compose.override.yml` 覆盖）再重启，然后用浏览器直接访问 AI 端口 | **不通**（只有后端可达） |

## 二、登录　（契约 6.1 · 第四节）

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| B1 | 正常登录 | 用演示账号登录 | 200；信封 `code=0`，`data` 含 `token` / `tokenType`=`"Bearer"` / `expiresIn`（秒）/ `user{id,username,roles}` |
| B2 | 密码错 | 密码故意写错 | **401 + `2004`**；`message` 是**能看懂的中文**；**不暴露堆栈、表名、类名** |
| B3 | 账号不存在 | 用一个不存在的账号 | 返回**与 B2 完全一样**的 `2004`（防撞库：两种失败长得一样） |
| B4 | 缺参数 | 不传 `username` | 400 + `1001` |
| B5 | 超范围 | `username` 传 65 字符 | 400 + `1003` |
| B6 | 格式错 | 传非法 JSON / 类型不对 | 400 + `1002` |
| B7 | 未知字段 | 多传一个契约里没有的字段 | 按契约"**不接收未知请求字段**"处理 → 400 + `1002` |
| B8 | 失败也有信封 | 对比 B1 与 B2 的响应体结构 | **结构完全一致**，只是 `code`/`message`/`data` 的值不同 |

## 三、登录态恢复与失效　（契约 6.2 · 第四节）

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| C1 | 取当前用户 | 带有效 token 请求 ② | 200；`data = {id, username, roles}` |
| C2 | 不带证 | 不带头请求 ② | **401 + `2001`** |
| C3 | 伪造证 | 随便改一位 token | **401 + `2001`** |
| C4 | 过期证 | 用已过期的 token | **401 + `2002`** |
| C5 | 刷新保持登录 | 登录后刷新页面 | 仍是登录态（前端用本地 token 调 ② 核验） |
| C6 | 失效的处理 | 触发 `2001` / `2002` | **清掉 token 并跳回登录页** |
| C7 | 无权限不跳登录 | **本阶段不适用**：骨架不实现六角色，没有能产生 `2003` 的路径（契约第四章） | —（等角色规则落地后再补这一项） |
| C8 | 登录失败留在原地 | 触发 `2004` | **留在登录页**，不跳转 |
| C9 | 网络错误 ≠ 密码错误 | 后端关掉后再点登录 | 提示"连接失败"，**绝不能提示"账号或密码错误"** |

> **C6 与 C8 必须分开测**：两者都是 401，但处理完全不同——这是最容易被搞错的一处。

## 四、占位列表　（契约 6.3）

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| D1 | 能取到 | 带 token 请求 ③ | 200；`code=0` |
| D2 | 数组形态 | 看 `data` | **直接是数组**，**不是** `{list: [...]}` 这种再包一层 |
| D3 | 两条占位数据 | 看内容 | `id` 为 1、2；`name` 为占位命名 |
| D4 | 时间格式 | 看 `createdAt` | ISO-8601 **带时区**（如 `+08:00`），**不是时间戳数字** |
| D5 | 字段永远在 | 检查每条记录 | 契约里列出的字段**都存在**（没值的给 `null`，不是省略） |
| D6 | 没带证 | 不带头请求 ③ | 401 + `2001` |
| D7 | 不查库 | 看实现或临时停掉数据库连接 | 该接口**不依赖数据库**（数据硬编码在 Service 里） |

## 五、贯通流 · 正常路径　（契约 6.4 · 6.5 · 5.1）

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| E1 | 请求打得对 | 打开浏览器网络面板，点按钮 | 是 **POST**（不是 GET），路径 `/api/v1/sample/analyze`，**带 `Authorization` 头**，token **不在 URL 里** |
| E2 | 首帧 | 看事件流 | 第一帧是 `meta`，**只发一次**，含 `traceId`（16 位小写十六进制）与 `sessionId`（UUID） |
| E3 | 中间帧 | 看事件流 | 全是 `delta`，每帧 `content` 是字符串 |
| E4 | 收尾 | 看事件流 | 最后一帧是 `done`，`finish === true` |
| E5 | 逐段而非一次 | 观察页面文字 | 文字是**一段一段蹦出来**的，不是卡一下全出来 |
| E6 | 响应头齐全 | 看响应头 | `Content-Type: text/event-stream`、`Cache-Control: no-cache`、`X-Accel-Buffering: no` **三条都在** |
| E7 | 字段转换正确 | 对照契约 **6.5 转换表**逐项核 | `message` = 前端 `prompt` 原文；`userId` = 登录身份的用户 id；`sessionId` = 后端新生成的 UUID；`traceId` = 本次请求追踪号 |
| E8 | 前端不传身份字段 | 看请求 body | 前端 body 里**只有** `spaceId` 与 `prompt`；**没有** `userId`、`sessionId` |
| E9 | sessionId 不复用 | 连点两次 | 两次的 `sessionId` **不同** |
| E10 | spaceId 只校验 | 传一个不存在的 `spaceId` | 返回 400 + `1003`（只校验存在性，不参与业务） |

## 六、贯通流 · 失败与边界　（契约 5.2，★这一节最容易漏）

### 6.1 A 段：尚未提交流式响应

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| F1 | AI 服务不可用 | 停掉 AI 服务后点按钮 | **HTTP 503 + 统一信封 JSON**（`code=5001`）；**一个 SSE 事件都不产生** |
| F2 | 上游返回非 200 | 让 AI 返回 500 | 同上 |
| F3 | 上游首帧不合法 | 让 AI 的 `meta` 缺字段 | 同上 |

> **关键点**：这三项**不能**返回 200 再发 `error`——此刻还没开始吐数据，**该用状态码就用状态码**。

### 6.2 B 段与 C 段：已经提交了流式响应

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| F4 | 吐到一半上游崩 | 让 AI 在第 2 个 `delta` 后抛异常 | 前端收到 `error`（`code=5001`）；**之后没有 `done`** |
| F5 | 上游一直没数据 | 让 AI 连上后不发任何事件；等到 **60 秒**（后端看门狗，见契约 3.4 / 第七节 #8） | 后端**发 `error` 并关闭**，**不是一直挂着**；此刻前端**还没**到自己的 90 秒空闲超时 |
| F6 | 上游不发终止事件就断 | 让 AI 发完 `delta` 直接关连接 | 后端**补发 `error`**；前端提示结果不完整，**不能当成正常结束** |
| F7 | 用户取消 | 吐字过程中点"停止" | 前端**立即停止渲染**并提示已取消；后端关闭上游流 |

### 6.3 解析健壮性（前端）

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| F8 | **半帧** | 一个事件被拆成两个网络分片 | 前端仍能正确拼出该事件 |
| F9 | **粘帧** | 两个事件挤在同一个分片里 | 前端能拆出两条 |
| F10 | **中文被拆开** | UTF-8 多字节字符跨分片 | **不出现乱码** |
| F11 | **CRLF** | 行尾是 `\r\n` | 解析正常 |
| F12 | 未知事件 | 上游发一个契约外的事件名 | 前端报"格式异常"，**不静默吞掉** |

## 七、追踪　（契约 3.3 · 6.7）

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| G1 | 格式 | 看响应头 | `X-Trace-Id` 是 **16 位小写十六进制** |
| G2 | 头与体一致 | 对比响应头与信封里的 `traceId` | **完全一致** |
| G3 | 后端自己生成 | 前端故意不传 `X-Trace-Id` | 后端**仍然**返回一个合法的追踪号 |
| G4 | **一个号串两边** | 拿这次的 traceId 分别去后端日志和 AI 服务日志里搜 | **两边都能搜到同一串日志** |
| G5 | 头体不一致要拦 | 让请求头与 body 的 `traceId` 不同 | AI 返回 **400 + `1002`**，**不进入流式** |

> **G4 是这一节的核心**——追踪机制存在的唯一理由，就是排障时能把两个服务的日志串起来。

## 八、边界与约束　（契约 一 · 八）

| # | 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- | --- |
| H1 | 前端不写后端地址 | 搜前端源码 | **搜不到** `localhost:8080`；只写 `/api/...` |
| H2 | 浏览器不直连 AI | 看网络面板 | **没有任何**指向 AI 服务端口的请求 |
| H3 | 没有密钥泄漏 | 检查被提交的文件 | 真实密码 / key **不出现在任何被提交的文件里**；`.env` 不在版本库 |
| H4 | 表结构 ≠ 接口 | 看数据库 | 建表脚本只管表；**接口契约不描述表结构**，两者不互相替代 |
| H5 | 冲突以契约为准 | 发现实现与契约不一致 | 停下来，**先改契约（在群里说）**，再改实现 |
| H6 | 不该存在的请求也套信封 | 请求一个不存在的路径 / 用错方法 / 发错 Content-Type | 分别返回 **404 + `1004`**、**405 + `1005`**、**415 + `1006`**，body 是**统一信封**（不能是框架默认错误页） |

## 九、结果记录方式

每项记三样：**通过 / 不通过**、**现象**、**traceId**。**结果写进 `docs/验收结果_<日期>.md`**（每次验收新建一份，不属于生效版文档）——别只口头过一遍，否则又变成"只有标准、没有结果"。

**不通过的写法要求**：写"点按钮后 3 秒页面报 X，traceId=..."，**不要只写"流式失败"**。

## 十、本阶段明确"不验收"的内容

并发容量 · 真实模型输出质量 · 生产可用性 · 六角色权限规则 · 多轮会话 · 审批流 · 向量检索 · 测试执行器。

> 这些不是"忘了"，是**本阶段范围之外**。列在这里，是为了防止有人拿它们当"没做完"。
